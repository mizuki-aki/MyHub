微信小游戏后台「版本管理 → 提交审核」要填的所有图片和文字，都在这两个目录：
本目录（`docs/store/`）放图标与文案，`screenshots/store/` 放游戏截图。

## 截图

微信后台要求 3~5 张，本套给 5 张（`screenshots/store/`）：

| 文件 | 画面 | 想传达的 |
|---|---|---|
| `01_cover.png` | 封面 | 标题 + 小鱼 + 公路 + 补给囊，定调 |
| `02_travel.png` | 白天行进 | 核心玩法：撞开悬浮球搜刮，路面纵深 |
| `03_dusk.png` | 黄昏布防 | 五种建筑摆在路上，策略感 |
| `04_night.png` | 夜战 | 怪物成群、篝火与塔挡在车前，紧张感 |
| `05_over.png` | 结算 | 一局结束的数据统计，说明有成长 |

规格：1170×2532（iPhone 12/13/14 Pro 原始分辨率），PNG，单张 190~810 KB。
全部由 `tools/shot.mjs` 以 3 倍设备像素渲染，**注入了真机安全区内边距**（顶部 29、底部 17 逻辑像素），所以 HUD 与底部按钮的位置就是 iPhone 上的真实位置。

`01b_continue.png` 是"有存档时"的封面（继续按钮），留档用，一般不必上传。

重出截图：

```bash
node tools/shot.mjs "file://.../tools/harness.html" screenshots/store/02_travel.png 390 844 1600 \
  "YY.start();YY.sim(36);var s=YY.S(),g=0;while(s.stage!=='travel'&&g++<3000)YY.tick(0.1);for(var i=0;i<40;i++)YY.tick(0.1);YY.simSafe(29,17);'ok'" 3
```

最后一个参数 `3` 是设备像素比，决定出图分辨率。

## 简介文案（后台填，限 4~120 字）

**推荐（62 字）**

> 一辆车，一盏灯，一条走不完的路。白天撞开悬浮的补给囊搜刮材料，黄昏把篝火与箭塔摆在车前面，夜里守住它。一百天内走到路的尽头。

**备选（73 字，信息更全）**

> 天亮了也是灰的。开着一辆灯还亮的车往前，白天撞开路上的补给囊换材料，黄昏把篝火和箭塔摆在车前面，夜里守住它。一百天内走到路的尽头，那里是救援中心。

**短版（51 字，适合列表页截断显示）**

> 永夜之后，只有车灯还亮着。白天换道撞开补给囊，黄昏布防，夜里守车。一百天，走到路的尽头。

口径说明：简介里不出现"多少户"——户是内部计算单位，玩家侧一律说"路的尽头 / 百分之多少"。这是项目一贯的文案规则，商店文案也照此执行。
